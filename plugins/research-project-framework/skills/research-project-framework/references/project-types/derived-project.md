# 补充:派生或扩展项目

从已有项目派生(复用它的数据与代码写新稿),或把已有论文扩展成新稿(例如会议版扩展成期刊版),都按这份来。下文把已有的那个项目叫母项目,它的论文叫母论文。这份里的规则在冲突处优先于核心文档。

**例子:** 核心框架的边界规则是「只读项目内的文件」「不提用户别的论文」。派生项目处处要对照母论文、核母项目的设置和数字,照字面做,助手连母项目的运行记录都不能看。

## 1. 开张

- CLAUDE.md「已确立的事实」登记:母项目路径;母论文的状态(在审、已录用、已发表)和出处;复用的数据与代码锁定在哪个提交;母项目里沿用的已定事实。已定事实只写一句并指向母项目决定表的那一行,不整段抄。
- 仓库(优先于 SKILL.md 开张清单里建仓库那一步):代码仓沿用母项目的,开一个新前缀的分支;论文仓,派生短文新建,扩展稿沿用并给母论文终稿打标签;只新建项目库。新建一个代码仓等于复制一份代码,和母项目的提交历史就断开了。
- 边界例外(优先于 `references/collaboration.md` 第 4 节):母项目的路径可以读;母论文不算「用户别的论文」,可以主动拿来对照。这两条写进 CLAUDE.md 的边界规则,因为 CLAUDE.md 每个会话都会读。

## 2. 引用与披露(优先于 `references/writing-workflow.md` 第 2 节第 6 步)

- 母论文已发表:照常引用;双盲时按场地要求的方式引用。
- 母论文在审:照目标场地对相关在审稿件的规定办,多数双盲会议要求匿名引用,或者向程序委员会披露。不能简单地不引:那样交代不了数据和代码的来源,还可能被当成重投。
- 首页或引言写明本稿和母论文是什么关系。

## 3. 重叠核查(投稿前)

- 核本稿和母论文在文字、图、结果上重叠多少。派生短文不能是母论文的重投。
- 沿用的文字和图,要符合母论文的版权或许可,以及目标场地的重用规定;这两样由用户核原文。

## 4. 数字可比

- 开张时记下母项目用的模型版本、托管方、提示词、种子和软件版本,作为可比的基线。
- 沿用的结果默认不重跑;重跑了结果不同,稿子里写明差异和原因。
- 付费 API 的模型几个月后可能下线或更新,补做的实验和母项目的数字未必能比,这一点也写进稿子。

## 5. LLM 是被评对象时(优先于 `references/research-workflow.md` 第 5 节)

- 第 5 节的「LLM 标注人当人类标注人对待」只适用于 LLM 在帮忙贴标签的情形。如果研究的就是 LLM 判断得对不对,参照只由人类按事先定的程序裁决,模型的判断不进参照;给模型的提示词和编码本一样,在看结果之前冻结。
- 拿模型与人的一致率评估模型是研究内容本身,不违反「不按一致率挑标注人」。
- 要把数据集里的图像发给付费的多模态 API 之前,先核数据集的许可和厂商的数据保留条款。
