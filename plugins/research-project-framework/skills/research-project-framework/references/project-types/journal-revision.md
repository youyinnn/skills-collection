# 补充:投期刊

包括把会议论文扩展成期刊版,以及审稿后的大修。会议论文扩展的部分,同时照 `references/project-types/derived-project.md`。这份里的规则在冲突处优先于核心文档。

**例子:** 核心框架的优化清单规定「优化不能越改越长」。期刊扩展和大修时,引言要加扩展声明和新贡献,相关工作要补后来的文献,审稿人要的解释多半是加字;照这条卡长度,会和期刊的要求顶着。

## 1. 开张

- CLAUDE.md「已确立的事实」不写截稿日和页数,改写:目标期刊、审稿方式(单盲还是双盲)、扩展稿政策(新增内容的比例要求、要不要上传会议版)、当前是第几轮、这一轮的修改期限。仪表盘标题改成「第 N 轮 · 修改期限 <日期>」。
- 扩展稿:会议版终稿冻结进 `inputs/`,只读。建一份新增清单,每项写它对应哪几节、哪些实验;用脚本对照会议版算新增比例,结果写进「已确立的事实」。

## 2. 写作上和会议不同的地方(优先于 `references/writing-workflow.md`)

- 起稿的材料,除了提案、分析产物、精读笔记,还有会议版正文和本轮审稿意见。逐句表加一栏「相对会议版:沿用、改写或新增」。
- 优化时长度只报不卡;新加的字要对得上新增清单里的某一项,或某一条审稿意见。
- 模拟评审:给评审代理会议版和差异说明,再加一位专评「新增够不够」的;修订轮另开代理,逐条核真实审稿意见改到没有。
- 匿名与自引按审稿方式办:单盲时不做匿名检查,首页写明扩展自哪篇并引用它。

## 3. 审稿意见与回复信

- 每一轮的编辑决定信和审稿意见,逐字存进 `records/reviews/<轮次>/`,按 R1.1、R1.2 编号,不进扫描与改写;每条意见开一张任务卡。
- 回复信每条四栏:意见、回复、改在哪、改后的原文。不同意时给理由和证据。交稿前核两件事:每条都有回复;回复里引的原文在终稿里逐字存在(稿子后来再改,引文就会过期)。
- 要用 AI 腔扫描检查回复信时,审稿人的原文放进引用块,扫描跳过引用块。

## 4. 标出改动

- 每次投出的版本,给论文仓打一个标签。
- 对上一轮的标签生成标出改动的版本(例如用 latexdiff),源文件里不手工加标记;干净版和标改动版一起交。基线是上一轮投出的版本,不是会议版。

## 5. 投稿材料

- 说明信、相对会议版的差异说明、推荐或回避的审稿人。
- 会议版的版权或许可、期刊对扩展稿和重用的规定,由用户核原文。
