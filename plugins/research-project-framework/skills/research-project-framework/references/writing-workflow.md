# 写作工作流

开张时这份文件会原样拷成项目的 `tracking/Writing-workflow.md`,以后项目里的写作做法有变,改那份副本。文中 `references/`、`assets/` 开头的路径指 skill research-project-framework 里的文件,`scripts/`、`tracking/`、`records/` 等指项目里的目录。

## 1. 先量范文

1. 选目标场地近两三年的论文作范文,PDF 转 markdown。
2. **换场地:先改切法,再对齐。** 量范文用的脚本(`scripts/*_stats.py`,见第 4 步)靠章节标题切节,切法是按某一个场地的标题写法定的,换一个场地就要重做这一步,做完才能量:
   1. 跑各节脚本的 `--dump`,看被跳过的论文和切出来的文本。
   2. 改切法。要按目标场地改的规则有四类:
      - 认节标题与节号:`intro_stats.py` 的 `_HEAD`、`INTRO_HEAD`、`REFS_HEAD`;`relwork_stats.py` 的 `HASH_HEAD`、`BOLD_HEAD` 与 `headings()`(背景、方法、讨论、结论也用它);`results_stats.py` 的 `HASH_HEAD` 与 `headings()`(威胁、讨论、结论也用它);`abstract_stats.py` 的 `ABS_HEAD`、`ABS_INLINE` 与 `cut_abstract()`。
      - 认「这一节算哪类」的节名规则:`background_stats.py` 的 `BG`;`methodology_stats.py` 的 `DESIGN`、`METHOD`、`RESULTS`、`EVAL`;`results_stats.py` 的 `START`、`END`;`threats_stats.py`、`discussion_stats.py`、`conclusion_stats.py` 的 `TITLE`(结论另有 `END`)。例如现有的 `DESIGN` 不认单独叫 Method、Methods 的节。
      - 清洗规则:`intro_stats.py` 的 `NOISE`(版头、版权行、页脚这类噪声,现有的是按 ACM 版式写的);`abstract_stats.py` 的 `NOT_PROSE`、`STOP`。
      - 逐篇的人工标注:引言的段落功能全部来自 `intro_stats.py` 的 `HAND`,换一批范文就要逐篇重标;各脚本开头的 `HAND_*`、`SKIP` 也按新范文重填。
      - 各脚本里标着「Assistant-set rules」的其余规则(主题、标记句)也是按 FSE 论文定的,对齐时一并抽查。量草稿的 `voice_stats.py` 拿范文作对照时用的就是这些切法,所以它也要等对齐以后再用。
   3. 对齐:每个节脚本抽 10 篇(不足 10 篇全看),逐篇对照原文核切出的那一节从哪开始、到哪结束,节内有没有残留的版头、版权行;有错就改切法,切法管不了的单篇写进该脚本的人工修正表(`HAND`、`SKIP` 等);改完重抽,直到抽查全对。
   4. 改过的切法在 `tests/` 里加一条用例(用目标场地一段真实的标题),跑全部测试。
   5. 对齐的结果(场地、抽了几篇、每节核对结果、跳过和人工修正了哪些论文)写进这个场地模板文件的「出处」。
3. 写论文类型编码本(例如研究型、方案型、工具型),独立做第二遍并报一致率;数字按类型分组报。本文属哪一类也按编码本判,记下依据句。
4. 每类节一个量法脚本(skill research-project-framework 的 `scripts/`、也就是开张时拷进项目的 `scripts/` 里已有摘要、引言、相关工作、背景、方法、结果、威胁、讨论、结论九节):有没有这一节、放在哪、长度、段数、句长、每百词引用组、公式与图表、单元主题、标记句。先量全,再定方案;量出的数不支持方案就停。只量一部分特征很容易漏掉关键的那一项(例如引用密度)。
5. 写模板文件 `records/findings/<场地>_<节>_patterns_<日期>.md`:出处、判断标准出自谁、数字来源、逐项规律、起稿槽位表、没做的。按论文类型另写一份,例句逐字核。
6. 草稿用同一把尺量(`measure_tex_section.py`、`voice_stats.py`):长度,加十项声音特征(第一人称、否定词、same、连接语、缓和词的密度,The 开头、冒号句、分号句的占比,句长变异,短句占比),对范文同类节的四分位。AI 腔主要在声音上,词表扫描只能查措辞。

范文只用来量形式,不借结构。套用范文写法时,填进去的缺口与理由必须有出处,没有就不写。

## 2. 从零起稿一节(十一步)

1. 量范文这一节(上一节)。
2. 写模板文件,用户看完说开始。
3. 列分配表:这一节要放的每条主张、定义、数字、引用,标出处,核没有一条已经写在别的节。
4. 起稿到论文仓:只用提案、分析产物、精读笔记三种材料(期刊扩展稿与工具论文另有材料,见对应的补充文件);一句一行;节标题按场地惯例;.tex 里不写注释、不放 todonote;没有出处的句子不写。改已有正文也先出逐句表:每句对模板哪个槽、留挪删、理由、新文。
5. 量草稿,超出范文范围的当场改再量。长度只报不议,用户提了才讨论;优化时例外(下一节第 1 项)。
6. 核每条新文献(`references/research-workflow.md` 第 3 节);自引用第三人称;在投未发表的不引(派生或扩展项目的母论文见 `references/project-types/derived-project.md` 第 2 节)。
7. 对改过的 .tex 跑格式化,编译,报错误行、未定义引用、页数;排版判断归用户。本机不编译时见 `references/project-types/collaborators-overleaf.md` 第 2 节。
8. 审稿人视角过一遍:按严重度列问题,每句答「该不该在这节」;句子层按第 5 节的风格规则过;决定变了就全文搜旧说法。
9. 改、再量、再编译;汇报照 `references/collaboration.md` 第 2 节。
10. 写会话日志。
11. 用户说「提交」才提交。

## 3. 优化已有一节(十五项清单)

用户说「优化某节」时逐项走,每项做完报一句:

| 项 | 做什么 |
|---|---|
| 1 | 量:长度、段落、句长、40 词以上、引用密度、十项声音。优化不能越改越长,长度要量要报(期刊扩展与大修时见 `references/project-types/journal-revision.md` 第 2 节) |
| 2 | 中文骨架(用用户的语言):一句一行,标它答哪个研究问题的哪一问或模板的哪一槽,别处已说的标出;末尾只列事实,不给建议 |
| 3 | 逐句归类:废话、冗余、不重要、惯例、承重,写依据;搜谁靠这句;复查三遍 |
| 4 | 按新骨架改英文;用户与合作者写的句子不动(要动合作者的句子先列给用户);参与者原话逐字不动 |
| 5 | 句子层:按 `references/writing-style.md` 第 3 到 6 节逐句过(用词、句子、标点、数字与缩写),加 AI 腔词表;跨句列出每个符号与自造词的定义句与使用句,查是不是一词一义、先定义后使用 |
| 6 | 可读性:改过的句子都过一遍,看读者能不能不靠猜读懂(主语、宾语、比较对象、条件、单位、逻辑连接有没有省掉);诊断与改后终审见 `references/writing-style.md` 第 7 节 |
| 7 | 审稿人视角:只按匿名稿看得到的东西预测意见 |
| 8 | 核事实:每个数对分析产物;改前改后比数字集合、引用与 `\ref` 集合;别节同一说法一致 |
| 9 | 再量,超出范文范围当场改 |
| 10 | 复查到零:每遍换一种查法(放回段落读;新旧对比找新毛病;对全文用词与原意),直到一遍零发现;汇报写复查情况 |
| 11 | 图表与图注(有才做):见第 6 节 |
| 12 | 格式化,编译 |
| 13 | 汇报:照 `references/collaboration.md` 第 2 节 |
| 14 | 记录:会话日志、CLAUDE.md 状态 |
| 15 | 提交:用户说才做,做法见 `references/project-management.md` 第 4 节 |

## 4. 几种专项做法

**压尾巴**(一段末行只剩一两个词,要让这段少一行或末行排满):在草稿副本上试;先列只删词不丢内容的候选(冠词、同段已说过的限定语、also、respectively),每处单试,量这段的行数与末行宽度;单处不够再试两两组合;不删事实、引用、用户或合作者定过的句子,不动参与者原话,不让第一人称或连接语掉出范文范围,不加括号指向别处;能收的有几种时取删词最少、不改意思的;要求压 N 个词而 N 个收不上时,做能收上的最小删改并说明。

**逐句要理由**(用户要求每段每句都给理由):逐句列后文谁用它、谁哪天定的、占哪个槽,这套标准是助手自立的要写明;后文没人靠、也没人定过的才列为最弱;只是理由形式上弱的不上清单;没有要改的只说不动;用户问「为什么留」而后文无依赖时默认删;开头段只说为什么问,怎么答放方法小节。

**模拟评审**:把论文快照编译在临时目录;五位审稿人(主编、方法学、领域、跨学科、唱反调的)各由一个子代理独立评,先只凭标题与领域写评分计划,再读稿,只看论文;按事先定的评分矩阵与失败条件综合成决定信与路线图;路线图按严重程度逐条讨论;改完另开核验代理问审稿人是否满意。

**引用核查**:只报告;分批交子代理,每条核元数据,每个引用处找原文逐字依据(网上的在浏览器里核,本地全文用搜索核);问题分元数据错、原文不支持、措辞三类,分高中低三级;用户点名改哪一级才改。

**语法检查工具**(如 Grammarly):它改对的几类写成标点语法规则,起稿时就照写;它常改错的几类(近义介词互换、给方法名加连字符、改动固定的量名、删字后不成句)记下来,再跑时先核这几类。

## 5. 写作风格

写成什么样(用词、句子、标点、数字与缩写、可读性、段落、图表的指向、LaTeX 源文件、检查工具)全部见 `references/writing-style.md`,这里不再重复。用户自己的写作规则(如有)也生效;与项目规则不同时,以项目规则为准。

## 6. 图表

图注写什么、正文与图表怎么对应、指图的写法见 `references/writing-style.md` 第 9 节;这里只管怎么做图。

- 任何布局提议先给草图,用一格真实数据画,同意后才改脚本。
- 图还在改的时候,不写图注与指图的句子;图定了再一次写。
- 迭代某几格时给的指令只管那几格,已定的格不动。
- 每张图一个生成脚本;图里的字体与论文正文一致。换版式时,出图脚本里的字体、字号、目标宽度一起换。
- 改论文里的图表要先得到许可。重跑生成脚本之前,先把它的输出写到临时目录,与论文里的那份比对,这一步可以直接做;用户或合作者的手改先同步进脚本。
- 改流程图工具(如 draw.io)的格子前,查挂在它上面的连线;写文件前看用户是不是开着这个文件;不复用格子 id。
- 问图表某部分要不要时,先准确回答前提,再盘点每部分承载什么;合并值背后逐单元的点显示分布,正文不提也要留。
- 裁切后的图宽对它所在位置的宽度核:单栏图对栏宽,跨栏图对版心(单栏版式两者相同);比该宽度窄得多的按原尺寸放,不拉伸。
- 整排面板要居中时,按裁切后的实际范围平移(matplotlib 的 `fig.get_tightbbox`),连同左边的行名一起算。
- 纵向位置用英寸算,再除以图高换成比例;这样改一块的高度时,其余各块的大小不变。
- 线宽减半时,matplotlib 的虚线段长会跟着缩短(`lines.scale_dashes`),要把虚线样式的数值加倍才保持原来的段长。
- 图里用数学模式写的上标星号(`$^{*}$`)会高到上一行,改用普通的 `*`;它在 Times 与 Linux Libertine 里本来就偏高。
- 把一块压矮之后,放大看点、菱形、柱有没有叠在一起。
- 半宽环绕表用 wrapfig 宏包的 `wraptable`,`\input` 放在讨论这张表的那段开头;列名要缩短才放得下,缩写的含义写进题注。编译后看那一页,表与段落有没有叠在一起。
- 图和表各占半宽并排:一个 figure 浮动体里放两个 `[t]` 的 minipage(各约 `0.485\linewidth`),每个开头放 `\vspace{0pt}` 让两边顶端对齐,表的题注用 `\captionof{table}`(caption 宏包提供,acmart 已加载)。半宽放不下的竖条图改横条,不整图缩小(字会小到看不清)。
- 编译后某个浮动体下面空白特别大时,先查日志里那一页有没有 `Underfull \vbox`:页底放不下的整块挪到下一页后,剩下的高度会摊进这段间距,不是浮动体本身占的。

## 7. 投稿前

| 事 | 做法 |
|---|---|
| 页数 | 用 PDF 库(如 pymupdf)读页数与每页文字,不用系统索引(会读到旧的) |
| 匿名 | 查论文仓全部跟踪的文本文件、`\input` 链里的注释、自引写法、bib 的注释字段、图的元数据、PDF 的 Info 与 XMP、复现包链接 |
| 场地要求 | 征稿页逐条核:页数、Data Availability、分类概念与关键词、AI 使用说明、作者账号信息;有人类参与者时的伦理与同意声明;作者名单与全部作者的同意(由用户确认) |
| 模拟评审与引用核查 | 第 4 节 |
| 声音 | AI 腔词表只查措辞,声音用量法脚本对范文量 |
