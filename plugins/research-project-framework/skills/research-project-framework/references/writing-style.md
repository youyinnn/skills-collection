# 写作规范

这份管论文正文写成什么样:用词、句子、标点、数字、可读性、段落、图表的指向、LaTeX 源文件,以及几个检查工具怎么用。按什么步骤起稿和优化见 `references/writing-workflow.md`;改动怎么交给作者看见 `references/collaboration.md`。

来源:作者在一次期刊大修中总结的写作指南;一份写作规范 skill;一个可读性 skill(第 7 节,改写自 MIT 许可的开源项目);标点与 Grammarly 改法的复查记录;几轮逐节优化里定下的做法。规则正文用中文,例句保留英文,例句都是编的。

## 0. 怎么用

- 优先级:目标场地的模板与写作手册,高于项目自己的规则(项目的 CLAUDE.md、`tracking/Writing-workflow.md`),高于本文件。
- 参与者原话与逐字引文不套本文件的规则(见 `references/project-types/human-participants.md` 第 8 节)。
- 起稿时照这份写,写的时候就写对,不等工具来改;优化一节时,写作工作流第 3 节的句子层与可读性两项按本文件第 3 到 9 节逐句过。

## 1. 原则

1. **先准确,再求字少。** 句子不对时,先找能让它变对、又保住原有信息的说法,之后才删多余的。保留作者的措辞和句子形状,只改错的部分;整句重写容易带进新毛病。
2. **只改错的或会误导的,除非作者要更多。** 自己主动审时,只对不实或会让读者得出错误结论的句子提修改。作者点名做某一遍(语法、清晰、压缩)时,这一遍针对的问题也算,其余不算。加一句话、一个限定、一个说明,要有审稿人或作者的要求,或者这句不加就是错的。
3. **每句都承重。** 改一句之前,说出它承载什么(服务哪个主张,后面哪句要用它),并核对改后还承载着。什么都不承载的句子删掉,不去润色;删之前列出它每个分句承载什么,还需要的放进留下的句子里。
4. **读者只有印出来的文字。** 按印出来的样子判断一句话,不带源文件注释、对话上下文或代码。讨论论文主张什么,以稿子为准;核方法句对不对,以实现为准,对不上就当作正文的错报出来。
5. **总结不能比被总结的说得多。** 摘要、贡献、回答框、结论只压缩正文,不加强正文。
6. **每个数都有已提交的出处。** 数来自已提交的表、图的数据或保存下来的输出,不来自临时重跑。数据重新生成后,从它读出的每个计数、排序、规律句都从头再推一遍。
7. **约定取最干净的终态。** 术语、缩写、格式,推荐最干净的最终写法,不推荐改动最小的;只给一个答案,不给选项。
8. **一致不靠投票。** 先判断哪种说法准确,出现次数多少不作数。两种都准确时,固定说法的价值在于告诉读者两句说的是同一个发现。
9. **在做决定的那一句里说明分歧。** 一句话做了选择,而两个判据结论不同,就在这一句里说;别处说过也要说。不是判据的描述量不算反证,不在决定处提。摘要、引言、结论复述这个选择时,不再重复说明。
10. **立场随事实变,不随压力变。** 被质疑时,重述依据;出现新事实才改结论。机器核过的事实与判断分开报。
11. **删改看内容,不看字数。** 判断一段文字看它清楚、正确、放对了地方没有;删的理由是重复、错位、没有依据,不是凑字数或页数。两种情况例外:作者要求优化某节时,改完不能比原来长(修句子常常要加字,同一轮里把多出来的压回去);作者提出版面要求(页数上限、段末那行只剩一两个词)时,按零代价删法压,不删事实、引用和限定语(做法见写作工作流的「压尾巴」)。
12. **问这句为什么在这一节。** 一句话可以又对又通顺,却该在别的节;挪个地方可能比润色更要紧。

## 2. 主张与证据

- 写有方向的句子(谁高谁低、变大变小)之前先读表;每个比较都说出跟什么比。
- 每个限定词(all、most、only、最极端的说法)都对着能推翻它的数据单独核,不只核旁边的数。
- 可能被单独引用的主张(摘要、总结、结论里的)自带范围限定;其他地方,一段开头说过一次范围,就管到这段下面各句。
- 规律句是全称判断:逐个实例核,有一个不成立,就报每个情况的实际值并点出例外,不写成规律。只对一部分对象(某几个数据集)说的规律,在其余对象上也核一遍。
- 每个计数在它出现的地方都能复算(`60 tests (10 datasets × 2 groups × 3 metrics)`),后面再提可以指回;每个 the、these、both 都找得到先行词。总数与分项要对得上。
- 计数放在原处会被误读时,把它挪进指向出处的那句,不另加一句推导。
- 正文里的结果数,在表、图或补充材料里都有。
- 指向某节、某表、某图的句子,所指的地方要真有它说的内容;写指向之前先打开目标看,目标改了再核一遍所有指向它的句子。
- 把一个计数放进摘要之前,和随机能产生的数比一下;等于随机期望的计数只是描述,证明不了什么。
- 数据确立不了的机制不当作发现写。
- 不做事后的检验力论证;说效应可忽略,要靠量出来的效应量。
- 每个方法句都对着实现(代码、配置、数据文件)核,不对着注释或记忆核。一节只描述真正跑过的分析。
- 被引的文献要真说过句子归给它的内容。
- 稳健性检查的正面结果写在结果节或补充材料里,局限一节可以用一个分句指向它。
- 论文用研究问题框和回答框时,问题框里的每一问,回答框都要答到,并沿用问里的动词。
- 像审稿人那样读每个主张,想想他接着会问什么。正文已经答了就不加;答不了的标给作者,不自己加字。审稿人只能看到匿名稿上印的东西,预测意见时不用作者身份这类匿名稿看不到的信息。
- **缺口句**不断言「没人做过」(`To our knowledge, no study has ...`),写成还不清楚的问题(`It remains unclear whether ...`、`Nor is it clear how far ...`)。要声明首创,得有成文的检索记录在背后。
- 套用范文的句式时,填进句式的缺口和理由必须有出处;没有出处,宁可不写,不为了填满句式编内容。

## 3. 用词

### 3.1 字面陈述

- 不用比喻和模糊修辞,判据写成可以逐项核对的字面说法。一句话去掉比喻就不成立,说明它本来没有内容,删掉。
- 不用从别的领域借来的术语和自己造的名目,写字面说法。例:两项指标此消彼长,不借用「零和」来说;一个差值不另起名字(如「安全余量」),直接写它是谁比谁低多少。工具论文的工具名和文中先定义后使用的术语不算(见 `references/project-types/tool-paper.md`)。
- 用常见、准确的词,不用生僻词;`leverage`、`utilize` 写 `use`。

### 3.2 定义与术语

- 论文自己造的词、在特定意义上用的词、每个符号,都在第一次出现处或紧接着定义(例如公式后的 `where` 分句)。领域通用的标准术语不用定义。
- 定义过的符号或缩写后面要再用到,用不到就删掉定义。
- 每个词、每个量的名字只指一样东西;部分和整体同名时,给部分改名。例:论文里「model」指被测的系统,就不能再用它指打分的 LLM,那个写 `judge`。
- 论文里有技术含义的词(significant、marginal、overall、optimal、test、power 等)全文不再随口用。只把 significant 留给统计显著时,直接写 significant;只有在把显著性和效应量对比、或读者可能读成「重要」的地方,才加 statistically。
- 定义里举的例子用编的;不点名读者还没见过的数据集,不提前报本文的结果。
- `namely` 引出完整的列举,`including` 引出部分列举;否定句里 `and` 换成 `or`。

### 3.3 程度词与评价词

- 不用含糊的程度词代替数字或结论(`modest`、`meaningful`、`small but significant`);程度副词紧挨着它的数可以。结论里用文字给出判断就够,这条不要求在结论里补数。
- 评价词和程度词带上它的数或出处(`state of the art`、`optimal`、`generally`、`only`、`representative`)。例:写 `weak` 时注明按哪种常规分档。
- 不用 `robust` 夸结果,写结果在什么条件下成立(`holds under three architectures and two metrics`);技术含义(robust standard errors、adversarial robustness)和引文照留。
- 不自夸(`rigorous`、`comprehensive`、`extensive`),也不和论文没量过的前人工作比高低;量过的比较是结果,不是夸。
- 正文里没有回复信的口气:不写修改经过,不对自己许诺,不和想象中的审稿人辩论。
- 适用于研究里所有对象的限定语,什么也区分不了(在「有效样本数」上写 valid,每个数据集都是长尾的还写 long-tailed),除非同一个词在别处指更大的范围。

### 3.4 口语说法

判据:日常口语常用、学术论文里有更正式的对应说法的,换掉。目标场地的范文里,作者自己的正文至少有两篇用过同样用法的,算场地接受,不换;没出现过的仍要逐个判断。

| 口语 | 换成 |
|---|---|
| `beats` | `outperforms`、`improves on` |
| `hand the choice to` | `delegate the choice to` |
| `move together` | `are related` |
| `up from 15` | `versus 15`、`compared with 15` |
| `get equal weight` | `have equal weight` |
| `nobody tells the model how to weigh it` | `the model is given no rule for weighing it` |
| `sits at 0.4` | `is 0.4` |
| `goes with` | `is associated with` |
| `run from 3 to 9` | `range from 3 to 9` |
| `cannot tell` | `cannot determine` |
| 图表标题 `Where the choices land` | `Distribution of the choices` |
| `Perhaps ...` | 有证据就直接写主张和证据;没有证据,写明是推测或删掉 |

### 3.5 拼写与大小写

- 全文统一一种拼写(美式或英式),引文与代码里的标识符保留原样。
- 节标题和段首小标题的大小写照目标场地范文的排法,全文一致。

## 4. 句子

### 4.1 一句一行

- 源文件一行一句,只在句号后换行;给作者看的笔记和引文也一样。
- 新内容默认写成段落;列表只给真能列举的东西(贡献、步骤)。

### 4.2 长句与拆句

- 40 词以上的句子考虑拆;短一些的句子,只在绕(一句说几件事、从句套从句)时才拆或调语序。
- 保持完整、不拆的:列举、阈值的定义、用括号加长的一个主张、用 so 或 as 连起来的链。
- 用 and、whereas、while 连起来的两个主张,在连接词处拆一次。
- **一个主语后面挂两段以上逗号修饰,拆开。** 形状是主句后面用逗号连挂两段以上、各带一件事的修饰或从句,逗号后常接 which、since、so、while、whereas、where、because、with … -ing、分词短语,或者一个数字同位语再加一个区间。读起来有明显的 AI 腔。改法:主句单独一句,后面的事另起一句,或者短的那件并进主句。并列列举不算这种形状。只挂一段的看情况:句尾单挂一段带数的分词短语(`, catching 41% of them`)可以留。查法:先用脚本数每句逗号后接上述词的段数,两段以上列为候选,再逐句人读;脚本漏的有两种,and 并列句后再挂从句,以及修饰语顶在短主句前面。
  - 例:`The linter can run the check at commit time without changing the build, as the default pipeline does while never reading the config, catching half of the errors.` → `The linter can run the check at commit time without changing the build. The default pipeline already does this without reading the config, and it catches half of the errors.`
- 拆开之后,单独读每一半:先行词在不在,范围对不对,和相邻句有没有重复。
- 拆开表转折或因果的连接词(`, but`、`, so`)时,把它变成句首过渡词并补上主语(`However,`、`Hence,`);在 and 处拆的不用加。

### 4.3 词级检查

- `, where` 只用在地点(表、图、数据集算地点)之后,或用来定义刚给出的公式里的符号。例:`three machines, where each has` → `three machines, each with`。
- 主语要能做这个动作。例:`the F1 score is used to save the checkpoint` → `the F1 score is monitored to save the checkpoint`。属性要归到它的主人:配置对性能有影响,模型有性能。
- 修饰语挂在它修饰的词上;引用跟在它所归功的内容后面;分词短语不悬空。
- 每个可数名词单数都有限定词(新出现、不唯一的用 a;前面提过或唯一的用 the);小标题的单复数一致。
- 不出现无意的回声:同一句、下一句、上面的小标题里重复同一个词(`CPU processor`、`split are split by`);关键术语反而要原样重复。每次替换一个词之后,把整句重读一遍。
- 同一个操作全文用同一个动词(通篇 `excluded`,不在别处换成 `removed`、`dropped`),免得读者以为是两个步骤。
- 连接词只在删掉它会丢掉一层关系时保留。常见的闲置词:`Specifically`、`Moreover`、`Notably`、没有「第一」的 `Finally`、`a total of`、`already`、`in order to`。
- 同一段说明(同一个提醒、同一个设置)出现两次的,合成一处。

### 4.4 连接与逻辑

- 没有建立起 so、therefore、because 所说的关系,就不用它们连句;并排放更诚实。
- `Yet`、`however` 只连真正相反的两件事。
- 不言自明的机理(增强的样本越多,算力花得越多)不需要证据,不标成「无依据」。
- 每句从上一句结尾的东西接起;引入一个新概念,通过上一句的宾语引出。
- 直接说出两句之间的关系,不写只预告下一句内容的句子;保留告诉读者「条件变了」的引导语(`In the second setting,`)。

### 4.5 人称、语态、时态

- 人称照目标场地范文的习惯定,全文只用一种人称、一个自称。写第三人称时,`this article` 作主语只放在交代全文做什么的句子里(`This article examines whether ...`);方法和设置节写被动,或以方法作主语。
- 被动语态可以用;只有它藏起了「谁做的」才改。
- 方法和结果用一般现在时,只有具体的过去事件用过去时。
- 表示必要用无人称动词(`requires`、`calls for`),不用 `have to`、`must`。

## 5. 标点

- 冒号只引出列举或公式;完整句之后引出列举用冒号(`in two settings: offline replay and live traffic`)。不用冒号引出解释或结果;括号里的标签可以用(`F1: 0.81`)。
- 分号不连两个分句,只在括号里的列举中分隔各项。
- 不用破折号插入,不用连接号连两个名词;用逗号、另起一句或普通连字符(`dataset-architecture`)。
- 不写 `rather than`;正面说出主张,或拆成两句。
- 不用加粗、斜体、引号作强调。
- 三项及以上的并列(and、or 都算),最后一项前加逗号,全文统一:`A, B, and C`;`0.01, 0.02, and 0.05`。
- 并列里套并列时,外层两项之间加逗号:`on 12, 9, and 7 of the 40 runs, and on 5, 3, and 2 of the rest`。
- and 连两个分句、后一句的主语可能被读成前一句的宾语时,and 前加逗号:`where 30 candidates pass the filter, and two reviewers disagree`。
- mean、median 后面接数时写 of:`a mean of 0.42`。
- 非限定成分、插入语两侧都加逗号:`the sampling parameters, other than the seed, at their defaults`。
- 句首分词短语的逻辑主语必须是主句主语,不是就改成介词短语:`Shown the score, each annotator labels` → `With the score, each annotator labels`。
- 句首或分句开头的状语(介词短语、副词、从句),不论长短,后面一律加逗号:`On each dataset, we average`;`Hence, the label alone`。例外:句首表转折的 Yet、But 后面不加;没有主语的动词并列里夹的状语也不加(`and in the second task compare`)。

## 6. 数字与缩写

### 6.1 数字(IEEE 惯例;场地自己的手册优先)

1. 带单位的数、测量值、计算出的值用阿拉伯数字。
2. 其他计数:一到十用英文单词,11 起用阿拉伯数字。
3. 句首的数用英文单词。
4. 同一个短语里的两个数(`7 to 13`、`X of Y`、区间),只要有一个是 11 或以上,两个都用阿拉伯数字。
5. 两个数挨着时,其中一个用英文单词(`ten 2D datasets`)。

- 括号里的乘式用阿拉伯数字(`(7 opponents × 7 datasets)`)。
- 千位分隔符照场地近年已发表论文的写法,与手册不同时以已发表论文为准。
- 正文里分数写 `57 of 80`,`57/80` 只出现在括号里。百分比和它的计数一起给时,计数紧跟在后面:`22.4% (11/49)`。
- 统计值照来源印出的样子原样抄。
- 改了数字格式之后,扫一遍正文里新格式已经印不出来的值(表里改印 `<1e-10` 之后,正文引的更小的 p 值就没了出处)。
- 手册没管到的情形列给作者定,不自创规则。例:不带括号的乘式(`three models by 12 settings`);同一句里一个小数字区间和 11 以上的数并列。

### 6.2 缩写

- 在阅读顺序里第一次出现时定义一次,之后只用缩写。摘要、关键词、图表标题里可以再定义。
- 定义了却不再用的缩写,删掉定义。
- 单独发布的补充材料自己定义它用到的缩写。
- 已经成词的缩写(AI、CT、MRI)不用定义;引用的方法名不展开。
- 先用后定义的,改成先给类别再给名字(`two other similarity measures, BLEU and ROUGE`)。

## 7. 可读性

本节改写自开源项目 matsuikentaro1/humanizer_academic 中的 reader-clarity 一文(MIT License, Copyright (c) 2025 Kentaro Matsui,基于 blader/humanizer,MIT),用我们自己的话重写,例句是编的,后半加了几轮修改里总结的做法。

一句话可以合语法,读者却得自己补出作者省掉的东西:谁做的、对什么做、跟什么比、在什么条件下、用什么单位、两个分句什么关系。目标读者懂这个领域,但英语不一定是母语,应该读一遍就懂。问题不在长度:不要把每个长句都拆开、把每个术语都展开,只修缺了的或有歧义的。

### 7.1 八条诊断

1. **抽象动词要说清改变了什么、跟什么比。** `we measure whether they use it and how their choices fare` 没说量的是什么;写成量什么、跟谁比(`how much of the gap their choices close, compared with the baseline`)。源头没说的,问作者或标 `[DATA NEEDED: ...]`,不编。
2. **每个代词在上下文里只有一个清楚的所指。** `Of the 120 answers, 115 cite the score. Their accuracy is ...` 里 their 会读成 answers;写成 `The annotators' accuracy is ...`。所指一看就明白的代词保留;把代词换成名词时不能多出一个主张。
3. **叠在一起的比较和条件拆开。** `on 3 of 12 datasets at 0.1 and on 7 and 9 of 14 at 0.2 and 0.5` → `on 3 of 12 datasets at 0.1, 7 of 14 at 0.2, and 9 of 14 at 0.5`。
4. **名词串改成有主语的动作。** `Developers list review guided by test coverage among the supports they lack` → `Developers say they lack support for reviewing code by its test coverage`。
5. **先说结果是在什么上算的,再暗示它在使用中意味着什么。** 在全部枚举过的基准上量到的数,不是预算有限时能拿到的;写 `On the full benchmark, the heuristic finds 80% of the bugs`,不写成对任何预算都成立的保证。
6. **直接说关系,不预告。** 删掉只预告下一句的句子;保留告诉读者条件变了的引导语。
7. **不让每段都以总结收尾。** 段末用抽象的话重述本段数字的句子删掉;解释数字、或把数字连回研究问题的句子留着。
8. **预告和结果对得上。** 摘要、贡献、方法概述说量了什么,结果里就要报;报不了就删掉预告。不要为了每个话题都留下,把每个结果压成缩写式的半句。

### 7.2 补充

- **不在句子中间插定义。** 定义放在它自己的分句或句子里,或者放在句尾括号里。
- **不套关系从句。** `..., which for the programs we study are call graphs, each linking ...` → `For the programs we study, the dependency structure is a call graph, which links each function to the functions it calls.`
- **不省略动词。** `the second whether the cache is worth keeping` → `The second decides whether ...`。
- **单位不错配。** 把一个比例和一个绝对值说成同一个东西(`The 40% speedup is the saving of 0.12`)不行;写成 `In seconds, this is a saving of 0.12`。
- **比较里说出变的是什么。** `The score changes the choices` 没说跟什么比;写 `showing the score changes the choices`,对照就是不给分数的时候。
- **比较对象、条件、单位要写全。** 例:`at 0.5` → `at a timeout of 0.5 s`;只在给与不给某项信息时成立的结论,写 `with the score shown or hidden`。论文的核心概念(例如一个选择规则和它的阈值),在它自己的一句里给出完整定义,不只在分词短语里带过。
- **同一种句型不连用三次。** 连着几句都是「主语加 with 分句」或「At X, Y」的,换掉其中几句的句型。
- **拆句不能带进新问题。** 拆完查:两句之间重复的开头、同一个对象一会儿 a 一会儿 the、把主语往后推的前置短语。
- **不替作者多说。** 作者写 choose、引用的文献写 compare 时,先看这一步是不是已经包含在作者的意思里,再决定加不加字。

### 7.3 压缩的顺序

1. 先找出必须留下的发现、比较条件和解释。
2. 先删重复的总结、空的预告、优先级低的句子,并核对挂在上面的引用支持的是什么。
3. 再删多余的短语,不删行为者、比较对象、条件和结果。
4. 重新计数,核对预告和结果仍对得上。不丢意思就达不到限额时,把取舍拿给作者看,不悄悄超出。

### 7.4 改后终审(每个改过的句子,放回它的段落里过)

- 读者能不能不靠猜就说出行为者、对象、比较对象、条件、单位?
- 每个代词、抽象动词、名词串在这里是不是有具体意思?
- 相关的比较是不是挨着,条件变了有没有提示?
- 每句是不是增加了一个发现、一个必要的条件、一个解释或一个必要的连接?
- 数字、引用、`\ref` 目标、技术术语和作者自己的句子是不是都保住了?(改前改后比数字集合和引用集合。)
- 改动是不是只在要求的范围里,没有编造缺失的信息?一节的可读性要求不授权改别处。

### 7.5 做法

1. **可读性单独过一遍,而且可以否决其他几遍。** 一句话准确、有出处、合文风,但读一遍读不懂,就算失败。放在精确和文风修改之后最后跑,凡是前面改过的句子都过。
2. **先说大白话,再翻译。** 用一句白话的中文说出这句(一个主语、一个主张),再译成英文;不要在草稿上一层层叠限定。
3. **开头的句子主语和动词在前,最多两段。** 不用长的前置状语,不绕道;论证的下一步交给下一句。
4. **核来源的主语,不只核主张。** 来源说的是 usability,就不能写成 user satisfaction。
5. **一般性的主张要引在原文里读过的文献。**
6. **预告里说量了什么,结果里就要有那个数。** 缺的数从结果节取,不从原始数据另算,让各节一致。
7. **每轮改动前后比数字和引用键。** 可读性修改不能改变数字、引用或 `\ref`;唯一允许的差别是拆句后重复出现的数。
8. **作者删掉或重写一句后,重读它的邻句**,看两边还接不接得上。
9. **提交前先比文件。** 作者可能在编辑器里手改过同几句,一起提交并说明。

## 8. 段落与删改

- 定义性的段落删掉复述上一句的句子,删掉「本文不研究什么」的否定范围句。
- 本文自己的实例用 `In this study,` 引出,和一般定义分开。
- 不机械地拆段;一段讲一件事,长度不是拆段的理由。
- 段首的加粗小标题说出这段报的是什么,不只说它属于哪一类(不写 `Observations.`,写 `Accuracy on Each Dataset.`)。
- 段末重述段首的收尾句删掉;解释或把数连回问题的收尾句留着。
- 删一句之前,先查后面有没有句子依赖它(别节的同一说法、标签引用),再列出它每个分句承载什么,还需要的放进留下的句子。
- 同一说法在别节的孪生句(摘要、引言、回答框、结论里的同一个发现)一起改,不只改一处。
- 压尾巴(段末那行只剩一两个词时删词让这段少一行)只用不丢内容的删法:冠词、同段已经说过的限定语、also、respectively;不删事实、引用、作者定过的句子,不改意思,不为收行加括号指向别处。具体步骤见写作工作流的「压尾巴」。

## 9. 图、表与指向

- 引用写成 `Figure~\ref{}`、`Table~\ref{}`、`Section~\ref{}`(不断行空格加标签),图的称呼照场地模板(ACM 写 Figure,IEEE 写 Fig.);不写死编号。
- 有自己编号的对象(表、图、带编号的框或条目)用编号指;可以加描述,但描述不能代替编号。用文字指位置(`above`、`the previous section`)时,读者要能不靠帮助找到,找不到就用编号。
- 同一段里已经引用过的图、表、节,不再引用(中间引用过别的除外);第一次引用照留。句子已经点名位置时,不再加括号 `\ref`(写 `as in the second experiment`,就不再跟 `(Section 3.3)`)。
- 图在小节开头句下面时,开头句把图写进句子里(`..., as Figure 3 shows`),不加括号;没有开头句的,在图上面写一句 `To answer RQ1, we ...`。
- 指向要落在真写着那件事的地方;打开目标再写指向,目标改了再核。
- 图注只留图上没标出来的东西(编码方式、数据来源、「数值是编的」);面板标题、图例、角注里已经印着的,图注不再写;重复正文指图句的也删。
- 正文引用的每个数都印在图上;正文说什么,图上就画什么。
- 显著性标记标在它所标的那个数后面,不放在标题上。
- 图和表分工:图上已经印的数,表里可以不重复;分工一变,重核所有指向这张表的句子。去掉一列之前,逐项核这一列还带着什么图上没有的东西。
- 图有毛病就改图,不在图注里打补丁。
- 生成图表、改图、布局的步骤见写作工作流第 6 节。

## 10. LaTeX 源文件

- 一句一行,只在句号后换行。
- 每个引用前用不断行空格(`Table~\ref{}`)。
- 交叉引用走标签或项目自己的宏,不写死编号。
- 裸数字统一一种写法(正文或数学模式),负数用数学模式以得到减号;指数写 `$10^{-5}$`,不写 `1e-5`。
- 特殊字符转义(`95\%`、`model\_v1`、`R\&D`),撇号用直引号。
- 交出或投稿的版本编译零错误、零未定义引用,源文件里不留 `\todo`、过时的宏和中文。

## 11. 工具

- **Grammarly:** 标点和拼写的改法基本照收;语态、冠词、介词、单复数的改动,对着全文的写法核。它常改错的几类,收之前先核:
  - `beside`(与……相比)被改成 `besides`;
  - `Over all candidates` 被改成 `Overall`;
  - 方法名被加连字符;
  - 固定的量名被改;
  - 动名词主语被当成分词(`choosing ... picks`、`showing the score changes`);
  - 前置宾语的图注被拆成并列;
  - 同位语后的逗号被删;
  - 删字后句子不成句(`They give up a mean` 改成 `They give mean`);
  - 表示范围的词被删(`there`)。
  改回时写明理由。
- **humanizer:** 只认它词表里的模式,术语问题另列。它会把 Title Case 的标题报成 AI 腔,这一条不改,大小写以目标场地范文为准。词表扫不出句式上的 AI 腔:另用声音特征对着范文同类节的四分位量(第一人称、否定词、The 开头、冒号句、分号句的占比,句长变异,短句占比,连接语、缓和词的密度),超出范围的按声音改;改后比数字和引用集合核事实。
- **可读性(第 7 节):** 放在精确与文风修改之后最后过。

## 12. 常见错误

写的时候:

- 总结比正文强:正文没证明的 all、only,或者一整类的名字。
- 凭记忆写方向,和表相反。
- 单独读是对的句子,和另一节的孪生句矛盾。
- 设计改了,数还是旧的;推出来的计数换了却没重算。
- 方法描述和代码对不上。
- 主张所依据的分析用错了人群或尺度。
- 一个术语两个意思。
- 对的句子放在错的节:结论里写统计量,局限里写借口,方法里写预测。
- 收尾句重述论点或给证据打分。
- 开头只点出一个困难,没说出因果上的问题。
- 头条数字随机就能解释。
- 自己定的报告规则只在部分地方执行。

改的时候:

- 重写代替改正,把旧形状带过来又添新毛病。
- 删了后面句子依赖的东西。
- 替换一个词种下回声。
- 引入稿子从来不用的惯例。
- 核了数字就说整句核过。
- 从不完整的搜索里报出现次数。
- 在图注里打补丁,而不是改图。
- 标出一个合法的写法,却说不出它违反哪条规则。
- 孪生的两句只改一句。
- 编一个理由留住某样东西。
- 拆开后一半缺先行词或范围,或带着重复的尾巴。
- 为了一个分句删掉整句,丢了另一个分句承载的东西。
- 把推导写进正文来修一个放错地方的计数。
- 按「审稿人会不会在意」过滤之后宣布「没有别的了」。
- 把一个借口修得更精确,而不是删掉它。

## 13. 检查清单

**写完一句之后**

1. 每个 where、代词、the、these、both 都有着落吗?
2. 主语能做这个动作吗?每个修饰语都挂对了吗?
3. 每个评价词、程度词都带着数或出处吗?
4. 技术词都按技术含义用了吗?每个术语只有一个意思吗?
5. 每个连接词说的关系,正文都建立了吗?
6. 方向对着表核了吗?每个限定词对着能推翻它的数据核了吗?
7. 每个计数在出现处都能复算吗?
8. 它在摘要、引言、回答框、结论里的孪生句还一致吗?
9. 符合第 3 到 6 节的用词、句子、标点、数字和缩写规则吗?主语后有没有挂两段以上的逗号修饰?

**提改动之前**

1. 现在这句是错的或会误导吗?或者是作者要求的这一遍针对的问题吗?都不是,就停在这里。
2. 这句承载什么?改了还承载吗?
3. 改动是否避开了承重的句子和已裁定的句子,照顾到对比的两边,放在做决定的地方,改得尽量少?
4. 它有没有增加负担、生词、坏结构或重复?
5. 要删的话,每个分句承载什么?还需要的现在由哪句承载?
6. 要加的话,论文自己会不会推翻它?
7. 报告是不是自成一体:完整原句、完整新句、译文?

**数据或表改了之后**

1. 列出从它读数的每一句,包括摘要、总结和结论。
2. 从新数据重新推出每个计数、排序和领先者。
3. 逐个实例核每个规律句。
4. 核对正文引的值没有落在新格式印不出来的范围里。

**优化一节时**,按写作工作流第 3 节的十五项走;其中句子层与可读性两项按本文件第 3 到 9 节逐句过。
