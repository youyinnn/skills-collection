# 项目管理

## 1. 记录文件各管什么

**原则:一件事只写一处。** 别处要提,写一句加「见哪里」。同一件事写在两处,迟早改了一处、漏了另一处。

| 文件 | 放什么 | 不放什么 | 什么时候被读 |
|---|---|---|---|
| `CLAUDE.md` | 铁律、已确立的事实、工作规则、当前状态 | 做完的事、规则的来由 | 每个会话开头自动读全文 |
| 助手的记忆 | 每条规则的来由、用户的原话、出过的事;地点与工具用法 | 会变的状态 | 索引每个会话自动读,正文要会话自己打开 |
| `records/Decisions.md` | 用户或导师(有合作者时也包括合作者,见 `references/project-types/collaborators-overleaf.md`)字面上做过的决定:日期、谁、原话、落在哪、出处 | 助手的提议(要放就标明) | 查的时候 |
| `records/log/<日期>_<会话短名>.md` | 这个会话做了什么、数字、出处、没做的、没提交的 | 别的会话的事 | 接手、查经过时 |
| `tracking/tasks/`、看板、仪表盘 | 任务状态 | 任务内容的复述 | 看进度时 |
| `tracking/File-map.md` | 目录与文件在哪 | 手写的文件数量 | 找文件时 |
| `tracking/Risks.md` | 风险与开关状态 | | |
| `tracking/Writing-workflow.md` | 怎么写、怎么改 | 决定原文 | 写作时 |
| `archive/` | 移出的旧状态、冻结的旧文件 | | 查历史时 |

**CLAUDE.md 里每条规则要写全「做什么、不做什么」与例外。** 记忆正文不保证被读,要照着做的内容不能只放在记忆里;记忆里只放「怎么来的」。

## 2. 状态怎么记

- 任务状态只记在卡片的 `status` 字段(看板与仪表盘从卡片读),不在别处另记。
- 仓库算得出的事实(文件数、某路径在不在、看板与卡片对不对)不手写。由脚本生成或在每次编辑后核对,只报不改。
- CLAUDE.md 的「当前状态」只留现状与还开着的事;做完的事写进会话日志。这一节长了就逐字移进 `archive/claude_md_history_<年月>.md`,文件头写明移出日期、逐字未改、怎么读。
- 随已批准的工作而来的记录更新当场改,过时的说法一处不留。
- 决定变了,同一轮全文搜依赖旧决定的说法,逐处列出来改。
- 一个量的定义变了,所有算它的脚本一起改,走同一个函数,改完比对产物。
- 决定只记用户或导师字面上做过的,记之前核出处;不替用户记他没做的决定。

## 3. 目录

| 目录 | 放什么 | 规矩 |
|---|---|---|
| `inputs/` | 实验结果、语料、论文 PDF 这类原始材料 | 不改;有人类参与者时,身份数据(录音、带真名的转录稿、同意书)不放这里,见 `references/project-types/human-participants.md` |
| `derived/` | 脚本的产物 | 手改无效,下次运行会覆盖 |
| `records/` | 决定、日志、检索协议、发现、计划、导师意见的逐字记录 | |
| `tracking/` | 任务卡、看板、文件表、写作流程、风险 | |
| `work/` | 提案与草稿 | |
| `archive/` | 移出的旧东西 | |
| `scripts/` | 手写源码 | 放根目录,钩子按项目根目录调它(`${CLAUDE_PROJECT_DIR}/scripts/…`) |

目录按来源分。硬规矩只有两条:`inputs/` 不改,`derived/` 由脚本生成。其余规矩没有工具核对就守不住,不设。有人类参与者时加第三条:身份数据不进项目库,用 `.gitignore` 和读取禁止规则守住(见 `references/project-types/human-participants.md` 第 2 节)。

**三个仓库分开:** 项目库放提案、记录、分析脚本与产物;论文仓放 .tex、.bib、图表源文件;代码仓放训练、评估、数据加载代码,只在有代码时建。派生项目沿用母项目的代码仓(见 `references/project-types/derived-project.md`);论文在 Overleaf 上的,论文仓从 Overleaf 克隆(见 `references/project-types/collaborators-overleaf.md`)。

## 4. 几个会话并行

- 每个会话只写自己的日志,短名会话自取。
- 每张图一个生成脚本,几个会话改不同的图不会改到同一个文件。
- 论文仓要有编译锁,同时启动的编译排队,不互相截断中间文件。
- 提交只交本会话的文件和行:
  1. 暂存前对每个要提交的文件 `git diff`,只暂存本会话的块,不凭会话开始时看到的状态。
  2. 共用文件(CLAUDE.md、决定表、共用脚本)暂存「上次提交 + 本会话的行」:用白名单拼出要暂存的版本,`git hash-object -w` 加 `git update-index --cacheinfo` 写进暂存区,工作区不动。
  3. 论文 PDF 由暂存树检出(`git checkout-index -a -f --prefix=<临时目录>/`)后编译,再写进暂存区。论文在 Overleaf 上编译的,论文仓不提交 PDF(见 `references/project-types/collaborators-overleaf.md`)。
  4. 提交前看 `git diff --cached --stat`,不是本会话的路径退出暂存区;add 与 commit 不串成一条命令,别的会话可能已经往共享的暂存区里加了东西。
  5. 先提交论文仓,把它的提交号写进项目库的提交说明,再提交项目库。
- 没有任何会话日志记录的改动,是用户自己在编辑器里改的;随文件一起提交,并在汇报里点名。有合作者共改论文仓时这条不成立,先查是谁的改动(见 `references/project-types/collaborators-overleaf.md` 第 4 节)。
- 改了别的会话会用到的共用文件(例如把 CLAUDE.md 的一整节移走),给相关会话发消息说明。整节移动时,别的会话没提交的行会跟着进库,提交时说明。

## 5. 提交

- 只在用户说「提交」时提交,一次「提交」只管一次;不推送。也不要每做一步就问要不要提交,报一句「工作区有未提交的改动」即可。
- 代码仓只在用户指定前缀的分支上提交,不进 main;项目库与论文仓提交 main。
- 提交错了不自己用 git 修(reset、amend 都算),把确切的命令给用户。他让做时,先 `git log -1` 确认 HEAD 是本会话的提交。
- 与远端分叉时 merge(`git pull --no-rebase`),不 rebase,记录里引用的提交号才一直有效。

## 6. 与导师

- 什么时候联系导师由用户定;助手不把「要和导师沟通」当成待办提。
- 导师意见逐字记录,放 `records/supervisor/`,不进任何自动改写或扫描。合作者、审稿人的意见同样处理(见对应的补充文件)。
- 引用导师的方向时逐字保留原动词;改写要标明(见 `references/research-workflow.md` 第 2 节「自框自评」)。
