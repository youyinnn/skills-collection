# 教训索引

按出错类型把前四份与补充文件里的规则归一遍。这里只写类型与指向,规则本身在指向的那一节。

| 出错类型 | 是什么样子 | 管它的规则在哪 |
|---|---|---|
| 自作主张 | 没让做就做了:自己提交、没报计划就动手建大东西 | `references/collaboration.md` 第 1 节;`references/project-management.md` 第 5 节 |
| 该做的不做 | 已核实的错、自己的缺陷、用户说了「开始」的工作,仍列出来等批 | `references/collaboration.md` 第 1 节 |
| 没查就说 | 用没核实的话填空;没打开报告就说「审稿人没提」;把自己的分析说成用户的原话 | `references/research-workflow.md` 第 2 节「填空式断言」与第 3 节;`references/collaboration.md` 第 3 节 |
| 问题是自己立的 | 查证的前提或判据是助手自己定的,却当成用户或导师的要求 | `references/research-workflow.md` 第 2 节「问题本身没查出处」 |
| 改了别人的话再评 | 把导师的方向改写后再评估 | `references/research-workflow.md` 第 2 节「自框自评」 |
| 只做一半就报完成 | 对齐了一部分脚本就说对齐了;只做了单句能查的检查 | `references/collaboration.md` 第 3 节;`references/writing-workflow.md` 第 3 节第 5 项 |
| 第一遍没查完 | 要用户开口才复查 | `references/collaboration.md` 第 2 节「末尾写复查情况」 |
| 讲得用户看不懂 | 先给抽象的清单或规则 | `references/collaboration.md` 第 2 节「先举例」「用户说看不懂时」 |
| 记录过期 | 文件表、看板、记忆写的与实际不符 | `references/project-management.md` 第 1、2 节 |
| 一件事写在几处 | 改了一处,漏了另一处 | `references/project-management.md` 第 1 节 |
| 旧说法没清 | 决定或定义变了,别处和别的脚本还是旧的 | `references/project-management.md` 第 2 节 |
| 几个会话互相踩 | 提交带进别人的改动;撤销时撤错了提交 | `references/project-management.md` 第 4、5 节 |
| 越界 | 读项目外的文件;提用户别的工作 | `references/collaboration.md` 第 4 节 |
| 用错工具 | 在本机跑训练评估;用命令行调文献 API | `references/research-workflow.md` 第 3、4 节 |
| 写作:内容先于测量 | 先定方案再量范文,漏量关键特征 | `references/writing-workflow.md` 第 1 节 |
| 写作:图和字一起改 | 图每改一轮,附的图注就作废 | `references/writing-workflow.md` 第 6 节 |
| 写作:优化越改越长 | 修句子时只加字不删字 | `references/writing-workflow.md` 第 3 节第 1 项 |
| 冲掉用户的手改 | 重跑生成脚本覆盖了用户或合作者在编辑器里的改动 | `references/writing-workflow.md` 第 6 节 |
| 身份数据进了库 | 访谈录音、带真名的转录稿进了 git,或被助手读到 | `references/project-types/human-participants.md` 第 2、3 节 |
| 改坏了别人的文字 | 合作者的句子、参与者的原话被优化或压尾巴改动 | `references/project-types/collaborators-overleaf.md` 第 3 节;`references/project-types/human-participants.md` 第 8 节 |
| 没交代和母论文的关系 | 母论文在审就不引;和母论文的重叠没核 | `references/project-types/derived-project.md` 第 2、3 节 |
