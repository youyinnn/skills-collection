# 项目记忆:<项目名>

每条规则只写一两句,写全「做什么、不做什么」与例外;来由与用户的原话放在助手的记忆里,规则的展开在 skill research-project-framework 的 `references/` 里。这个文件每个会话开头都会被整份读,所以不放做完的事。

## 铁律(展开见 skill research-project-framework 的 `references/research-workflow.md` 第 2 节)

1. 定方向按顺序:目标场地与约束 → 用户的第一作者成果 → 这些成果欠了什么 → 有没有人做过 → 才谈怎么做。外部论文只用作场地信号或划界的对照,不当结构模板。
2. 影响决策的判断句,要么给可核验的出处,要么标「推测/无证据」;「没人做过」要标明检索性质。
3. 开始任何查证、评估、筛选之前,先写「本次判断标准出自:___」,写不出就标「我自立」;自己引入的新术语视同自立判据,要标出处、解释词义。
4. 不用比喻与模糊修辞,判据写成可逐项核对的字面陈述。跟用户说话时举真实案例;论文里不用借来的术语与自造名目,定义里的例子用编的,不点名还没介绍的数据集,不提前报本文结果。
5. 引用他人(尤其导师)的方向时,逐字保留原动词与原表述;改写要标明并说明为什么改。评估前先确认评的是谁的版本。
6. 用他人的话设定约束前,先确认那句话的完整语义,包括它的反面;不给可行的路加不存在的障碍。
7. 语料内「0 篇」不当利好;用于决策前补一轮语料外检索,并标明检索性质。
8. 同一份材料换用途,重新核它是否支持新用途。

## 工作规则

1. **不造代号。** 跟用户说话先说事情是什么,卡号、编号只放括号里作定位。
2. **记录。** 每个会话写自己的日志 `records/log/<日期>_<会话短名>.md`;决定只进 `records/Decisions.md`,只记用户或导师字面上做过的,进之前核出处;任务状态只记在卡片的 `status` 字段。
3. **一件事只写一处。** 别处要提就写一句加「见哪里」;仓库算得出的事实不手写,由脚本生成或核对;`inputs/` 不改,`derived/` 由脚本生成。随已批准的工作而来的记录更新当场改,过时的说法一处不留。
4. **改前先说,批了再改。** 判断与取舍类的改动(论文正文、提案)先说明文件、改什么、为什么,等用户批准;用户点名一件工作并说「开始」就是批准。以下当场改,改完报原文、新文与理由:记录更新;论文里已核实的事实错;自己写的东西里查出或量出的缺陷。例外:用户要的是「检查」时只报告问题、出处与建议改法,事实错也不改。跨多个文件或要新建文件的大任务,先报现状与计划,等用户说开始。问句只回答,不动文件。
5. **东西怎么给用户看。** 改动用带颜色的对比呈现:每处位置(文件与行号)、原句、新句(附译文)、一行理由;删掉的词标红划线,加上的词标绿;在 Claude 桌面版里用对话内嵌组件画,样式照 `tracking/templates/change-widget.html`,没有组件时用纯文字标法。交改动、核查结果、方案或清单时,末尾写复查了几遍、每遍的查法、最后一遍是不是零发现。讲解释、方案、清单时先举本项目一个具体的例子,再说规则。回复用用户的语言,外文附整句译文。
6. **提交。** 只在用户说「提交」时提交,一次一提,从不推送;只交本会话的文件与行(做法见 skill research-project-framework 的 `references/project-management.md` 第 4 节);提交错了不自己用 git 修,把命令给用户由他定。
7. **三个仓库。** 项目库(本目录,提交 main)放提案、记录、分析脚本与产物;论文仓 `___` 放 .tex、.bib、图表源(提交 main,每次改完 .tex 或 .bib 编译,报错误、未定义引用、页数,排版判断归用户;编译锁文件不进仓);代码仓 `___` 放训练、评估、数据代码(只在 `___/` 前缀的分支提交,环境 `___`)。
8. **算力与付费调用。** 模型训练与大规模评估不在本机跑,报成云 GPU 作业由用户排(单测、小例子可以跑,跑前说一句);调用付费 API 前报调用数、花销与耗时,等用户许可,跑完报 token、花销与耗时。
9. **文献。** 一切检索走浏览器,不用命令行或脚本调文献 API;PDF 统一用一种工具转成 markdown,逐字引文回 PDF 核。
10. **边界。** 只读项目内的文件与用户点名的文件;不提用户别的论文、课程、截止日期。例外:派生或扩展项目的母项目路径可读、母论文可以提;有人类参与者时,身份数据即使被点名也不读。
11. **写作。** 按 `tracking/Writing-workflow.md` 写;「优化某节」按其中的清单逐项走。
12. **触发词。** 「开始」「提交」「检查」「优化某节」按 skill research-project-framework 的 `references/collaboration.md` 第 1 节与 `references/project-management.md` 第 5 节的意思执行;工作语言不是中文时,对应的英文说法写在这里(见 skill research-project-framework 的 `references/glossary-zh-en.md`)。
